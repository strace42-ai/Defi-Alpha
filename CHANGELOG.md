# Изменения

## 2.1.2 (2026-11-05) — Global Discovery & UX
Основа — стабильная 2.1.1; незавершённый индексатор FABLES (ветка `claude/defi-alpha-2.2-fables-emission`) сюда не входит.
- **Фильтр 1 — фиксированная дата TGE** (режим A, по умолчанию): `TGE ≥ даты`, дата не сдвигается со временем, проект не выпадает
  через 90 дней. Дата вычисляется один раз при обновлении (сегодня − прежний порог в днях) и сохраняется в настройках.
  - Без подтверждённого TGE — UNKNOWN; дата первого пула или сделки показывается только как предварительный ориентир.
  - Торговля раньше даты доказывает, что токен старше: в этом случае FAIL.
  - Режим B (возраст ≤ N дней) сохранён. При смене даты решения пересчитываются, история решений фильтров не удаляется.
- **Сортировка любой таблицы** кликом по заголовку: по возрастанию → по убыванию → по умолчанию, со стрелкой направления.
  - Числа, деньги, проценты, дни и даты сортируются по значению; н/д и UNKNOWN всегда внизу.
  - Состояние запоминается для каждой таблицы и сохраняется при автообновлении.
  - Для постраничных списков сортировка идёт на сервере по всему результату.
- **«Лучшие кандидаты»**: весь рейтинг вместо первых 30. Поиск, фильтры (сеть, уровень, статус, MCAP, дата начала торгов), страницы,
  место в общем рейтинге и в своей сети. Выбор сети показывает её лучших независимо от первой страницы общего рейтинга.
- **Справедливый выбор между сетями**: токены для анализа, ончейна, фундаментала, CoinGecko и котировок внутри уровня приоритета
  чередуются по сетям (round-robin). Большая партия одной сети больше не занимает все места.
- **«Покрытие сетей»**: по каждой сети — обнаружение, пропуски покрытия, токены, анализ, связь с DeFi, уровни, рейтинг, FAIL по фильтрам,
  очередь, ошибки RPC, лимиты источников. Процент покрытия не выдумывается.

## 2.1.1 (2026-11-05) — исправление двух дефектов аудита 2.1.0 (только `app/emission_pressure.py`)
Подробно: `docs/audit/AUDIT_RESPONSE_v2.1.1.md`.
- **Использование бюджета.** Статус FINAL ставится, только если **каждый** mint эпохи доказанно отнесён к LP-эмиссии
  или к другой категории с подтверждённой ролью. Иначе — PARTIAL:
  - подтверждённая LP-эмиссия и нижняя граница «подтверждено ≥ X%»;
  - LP по роли без подтверждения;
  - неклассифицированный выпуск;
  - верхняя граница;
  - полная доля бюджета не выдаётся.
- **Уровень доказательности роли переносится точно**: `claimed` больше не превращается в `probable`.
  Доказательность группы определяется по самому слабому элементу.
- Метод `emission-1.1`. Результаты `emission-1.0` остаются в истории, пересчёт выполняется автоматически.
  Momentum и остальные модули не изменялись.

## 2.1.0 (2026-11-05) — аналитика, этап 1 (модули выключены по умолчанию)
Подробно: `docs/ANALYTICS_2.1.md`. Ветка `claude/defi-alpha-2.1-analytics`; стабильная 2.0.1 — коммит 08278d0.

- **Fundamental Momentum** (вкладка «Фундаментальный импульс»):
  - динамика TVL, комиссий, выручки и объёма за 7, 30 и 90 дней по дневным рядам DefiLlama;
  - TVL относительно своей сети и доля в ней;
  - эффективность капитала, структура комиссий, рыночная оценка;
  - вывод «улучшается / стабильно / ухудшается / недостаточно данных» с объяснением, достоверностью и источниками;
  - событие «экономика опережает оценку» как повод для исследования, не рекомендация.
- **Emission Pressure, этап 1** (вкладка «Эмиссионное давление», сводка в карточке токена):
  - Genesis, LP-эмиссия и неизвестные выпуски из уже собранных событий mint/burn;
  - точная сверка с totalSupply, эпохи, использование бюджета;
  - стоимость эмиссии по цене своей эпохи;
  - claims, ve-блокировки и продажи явно UNKNOWN (этапы 2–3).
- **Реестр ролей адресов**: сеть, токен, роль, источник, дата, достоверность, доказательство, ручное уточнение,
  предупреждение о конфликтах. Роли не переносятся между токенами и сетями.
- **Изоляция от сканера**:
  - отдельная очередь `analytics` с низким приоритетом, бюджетом времени и откладыванием при перегрузке;
  - ноль сетевых запросов (запрет в `http.client()`);
  - отдельные таблицы, которые создаются только при включении модуля;
  - пересчёт только при изменении входных данных.
- `python -m app --analytics-off` выключает оба модуля. `windows_check.bat` дополнительно выполняет стресс-тест с включённой аналитикой.
- Тестов: 140 (из них 25 — аналитика 2.1, включая обязательные проверки 1–16).

## 2.0.1 (2026-11-05) — аварийное исправление
Новых функций нет. Подробно: `docs/audit/AUDIT_RESPONSE_v2.0.1.md`, стресс-тест: `docs/STRESS_REPORT_2.0.1.md`.

- **SQLite (`database is locked`, гибель очередей).** Причина: после ошибки записи соединение потока оставалось с открытой
  транзакцией и держало блокировку записи бессрочно; запись статуса задачи вне `try` завершала поток очереди.
  Исправления:
  - явный режим транзакций;
  - единый слой записи `db.tx()` (сериализация, `BEGIN IMMEDIATE`, `ROLLBACK` при любой ошибке);
  - массовые записи порциями;
  - запрет сетевых вызовов внутри транзакции;
  - журнал ошибок в файл, не зависящий от базы;
  - неубиваемые очереди.
- **ATH, цена, пулы и связь с протоколом** больше не стираются при пустом или ошибочном ответе источника: прежние значения
  сохраняются с пометкой «устарело». Связь с протоколом снимается только при доказательстве изменения.
- **Обновление без потери базы:** если базы нет, но найдена прежняя установка, новая база не создаётся и предлагается перенос
  с проверкой целостности, сверкой строк, резервной копией и откатом (`--import-db`, `--rollback-import`).
  Если рядом найдена установка с бо́льшим объёмом данных, выводится предупреждение.
- **Действия интерфейса** выполняются атомарно и идемпотентно. При ошибке базы возвращается явный ответ 503, «успеха» без записи нет.
- **Проверка на компьютере пользователя:** `windows_check.bat` (`python -m app.selfcheck`).
- Регрессионные тесты: `tests/test_v201_regressions.py` (25). На коде 2.0.0 из них падает 21, подробный разбор в `docs/audit/`.
  Всего тестов 115.

## 2.0.0 (2026-11-05)
Обязательный релиз 2.0. Новых аналитических модулей 2.1 (Fundamental Momentum, Emission Pressure, новый рейтинг,
расширенные сигналы) и удобств 2.2 (автозапуск Windows, трей) в этой версии **нет**.

- **Пять обязательных фильтров**: No-VC убран из фильтров, уровней, статусов и интерфейса. Финансирование — аналитика рисков
  (раунды, суммы, оценки, отношение привлечённого к MCAP, разлоки инвесторов из токеномики).
- **Автоматический мониторинг** включается при первом запуске новой версии; четыре независимые очереди (котировки, обнаружение/анализ,
  ончейн, CoinGecko/сервис), дедупликация, ограничение длины очереди, приоритеты 0–5, circuit breaker для недоступных источников,
  ограниченные по времени задачи. Один экземпляр сборщика на папку данных.
- **Адресное обновление токенов**: открытая карточка (приоритет 0), «Наблюдение» (1), лучшие кандидаты (2)… Ончейн — только новые блоки
  с перекрытием 2000 блоков (события, исчезнувшие при реорганизации, помечаются `orphaned`, не удаляются).
- **Живой интерфейс** без перезагрузки: прокрутка, вкладка, поиск, сортировка и несохранённый ввод сохраняются; индикаторы
  «актуально / обновляется / источник недоступен / устарело / конфликт» с фактическим временем получения.
- **Скрытие из лучших кандидатов** (бессрочно / 7 / 30 дней), вкладка «Скрытые мной», восстановление, журнал действий.
- **Статусы наблюдения**: изучаю, наблюдаю, есть позиция, гипотеза под вопросом, архив.
- **MCAP Intelligence Engine**: многоуровневое определение капитализации, типы CONFIRMED/ESTIMATED/UNKNOWN, диапазоны и доказуемые
  границы, проверка цены (взвешенная по ликвидности медиана, свежесть сделок, сверка с DefiLlama, детектор скачков), CoinGecko
  с проверкой контракта, ончейн-вычет только доказанно заблокированных адресов, история оценок, очередь «MCAP требует уточнения».
- **Режимы сортировки**: сильные фундаментально, недавно обнаружены, активность при малой капитализации, предупреждения,
  ручная проверка, MCAP требует уточнения.
- **Миграция базы v1 → v2** с резервной копией, транзакцией и откатом (`python -m app --rollback-migration`).
- Исправлено: параллельные очереди могли затирать сводку фактов токена (теперь сохраняются только изменённые ключи).
