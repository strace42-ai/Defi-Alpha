# Изменения

## 2.0.1 (2026-11-05) — аварийное исправление
Новых функций нет. Подробно: `docs/audit/AUDIT_RESPONSE_v2.0.1.md`, стресс-тест: `docs/STRESS_REPORT_2.0.1.md`.

- **SQLite (`database is locked`, гибель очередей).** Причина: после ошибки записи соединение потока оставалось с открытой
  транзакцией и держало блокировку записи бессрочно; запись статуса задачи вне `try` завершала поток очереди.
  Исправления:
  - явный режим транзакций;
  - единый слой записи `db.tx()` (сериализация, `BEGIN IMMEDIATE`, `ROLLBACK` при любой ошибке);
  - массовые записи порциями;
  - запрет сетевых вызовов внутри транзакции;
  - журнал ошибок в файл, не зависящий от базы;
  - неубиваемые очереди.
- **ATH, цена, пулы и связь с протоколом** больше не стираются при пустом или ошибочном ответе источника: прежние значения
  сохраняются с пометкой «устарело». Связь с протоколом снимается только при доказательстве изменения.
- **Обновление без потери базы:** если базы нет, но найдена прежняя установка, новая база не создаётся и предлагается перенос
  с проверкой целостности, сверкой строк, резервной копией и откатом (`--import-db`, `--rollback-import`).
  Если рядом найдена установка с бо́льшим объёмом данных, выводится предупреждение.
- **Действия интерфейса** выполняются атомарно и идемпотентно. При ошибке базы возвращается явный ответ 503, «успеха» без записи нет.
- **Проверка на компьютере пользователя:** `windows_check.bat` (`python -m app.selfcheck`).
- Регрессионные тесты: `tests/test_v201_regressions.py` (25). На коде 2.0.0 из них падает 21, подробный разбор в `docs/audit/`.
  Всего тестов 115.

## 2.0.0 (2026-11-05)
Обязательный релиз 2.0. Новых аналитических модулей 2.1 (Fundamental Momentum, Emission Pressure, новый рейтинг,
расширенные сигналы) и удобств 2.2 (автозапуск Windows, трей) в этой версии **нет**.

- **Пять обязательных фильтров**: No-VC убран из фильтров, уровней, статусов и интерфейса. Финансирование — аналитика рисков
  (раунды, суммы, оценки, отношение привлечённого к MCAP, разлоки инвесторов из токеномики).
- **Автоматический мониторинг** включается при первом запуске новой версии; четыре независимые очереди (котировки, обнаружение/анализ,
  ончейн, CoinGecko/сервис), дедупликация, ограничение длины очереди, приоритеты 0–5, circuit breaker для недоступных источников,
  ограниченные по времени задачи. Один экземпляр сборщика на папку данных.
- **Адресное обновление токенов**: открытая карточка (приоритет 0), «Наблюдение» (1), лучшие кандидаты (2)… Ончейн — только новые блоки
  с перекрытием 2000 блоков (события, исчезнувшие при реорганизации, помечаются `orphaned`, не удаляются).
- **Живой интерфейс** без перезагрузки: прокрутка, вкладка, поиск, сортировка и несохранённый ввод сохраняются; индикаторы
  «актуально / обновляется / источник недоступен / устарело / конфликт» с фактическим временем получения.
- **Скрытие из лучших кандидатов** (бессрочно / 7 / 30 дней), вкладка «Скрытые мной», восстановление, журнал действий.
- **Статусы наблюдения**: изучаю, наблюдаю, есть позиция, гипотеза под вопросом, архив.
- **MCAP Intelligence Engine**: многоуровневое определение капитализации, типы CONFIRMED/ESTIMATED/UNKNOWN, диапазоны и доказуемые
  границы, проверка цены (взвешенная по ликвидности медиана, свежесть сделок, сверка с DefiLlama, детектор скачков), CoinGecko
  с проверкой контракта, ончейн-вычет только доказанно заблокированных адресов, история оценок, очередь «MCAP требует уточнения».
- **Режимы сортировки**: сильные фундаментально, недавно обнаружены, активность при малой капитализации, предупреждения,
  ручная проверка, MCAP требует уточнения.
- **Миграция базы v1 → v2** с резервной копией, транзакцией и откатом (`python -m app --rollback-migration`).
- Исправлено: параллельные очереди могли затирать сводку фактов токена (теперь сохраняются только изменённые ключи).
