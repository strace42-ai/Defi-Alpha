# DeFi Alpha Scanner

Локальная программа для автоматического **обнаружения и предварительной проверки молодых DeFi-проектов**
с небольшой капитализацией. Собирает данные из бесплатных публичных API и блокчейнов, применяет ваши
пять инвестиционных фильтров и **объясняет каждое решение** со ссылками на источники.

> Программа только читает данные. Не подключает кошельки, не просит seed-фразы и ключи, не совершает сделок.
> Результаты — материал для ручного исследования, а не рекомендация к покупке.

## Быстрый старт (Windows 10/11)

1. Установите **Python 3.11+** с https://www.python.org/downloads/ — при установке отметьте
   **«Add python.exe to PATH»**. (Или в PowerShell: `winget install -e --id Python.Python.3.12`.)
2. Скачайте папку проекта (кнопка **Code → Download ZIP** на GitHub) и распакуйте, например, в `C:\DefiAlpha`.
3. Дважды щёлкните **`start.bat`**.
   - При первом запуске программа сама создаст окружение и установит зависимости (1–3 минуты).
   - Затем откроется браузер со страницей `http://127.0.0.1:8765/`.
4. Ничего нажимать не нужно: **фоновый мониторинг запускается сам**. Через 1–3 минуты в «Сканере» появляются реальные
   новые токены, дальше они обновляются автоматически (без перезагрузки страницы).
5. Нажмите на тикер — откроется карточка: почему токен подходит или не подходит под каждый фильтр, с доказательствами.
   Открытая карточка и проекты из «Наблюдения» обновляются чаще остальных.

Остановить мониторинг — кнопка «⏸ Пауза» вверху; закрыть программу — закрыть чёрное окно. Повторный запуск — снова
`start.bat`: накопленная история сохраняется, сбор продолжается с сохранённых позиций, а пропущенные за время остановки
периоды показываются как разрывы покрытия. Второй экземпляр сборщика не запускается (повторный запуск просто открывает интерфейс).
Мониторинг работает, только пока программа открыта и компьютер не спит.

### Обновление до 2.1.2 (Global Discovery & UX)
1. Закройте окно работающей версии. Распакуйте ZIP **рядом** с прежней папкой и запустите `start.bat` из новой папки `DefiAlpha-v2.1.2`.
2. Программа найдёт прежнюю базу и предложит перенос. База **копируется**, оригинал в старой папке не изменяется; к нему можно вернуться.
3. При первом запуске фиксированная дата фильтра TGE вычисляется один раз (сегодня − прежний порог, обычно 90 дней) и сохраняется.
   Проверить или изменить её можно в «Настройки → Фильтр 1»; там же можно вернуться к режиму B (возраст ≤ N дней).
   После изменения фильтры пересчитываются автоматически, а история прежних решений сохраняется.
4. Наблюдение, скрытые токены, аналитика 2.1, котировки и база данных продолжают работать как раньше.

### Аналитика 2.1 (по умолчанию выключена)
Вкладки «Фундаментальный импульс» и «Эмиссионное давление» появляются сразу, но модули включаются только кнопкой
«Включить модуль» на вкладке. Пока модули выключены, программа работает и хранит данные точно как 2.0.1.
- Модули используют только уже собранные данные и не делают сетевых запросов. Они работают в отдельной очереди
  и не замедляют котировки и обнаружение.
- Выключить оба модуля: кнопкой на вкладке или командой `.venv\Scripts\python.exe -m app --analytics-off`.
- Вернуться к 2.0.1: запустить папку 2.0.1 с той же `data\scanner.db`. Таблицы аналитики 2.0.1 игнорирует, данные не теряются.
  Подробности в `docs/ANALYTICS_2.1.md`.

### Обновление до 2.0.1 с сохранением прежней базы
Все накопленные данные хранятся в файле `data\scanner.db` **прежней** папки программы. ZIP нового выпуска распаковывается
в новую папку `DefiAlpha-v2.0.1`, где этой базы нет.
1. Закройте прежнюю версию: закройте её чёрное окно.
2. Распакуйте ZIP **рядом** с прежней папкой (в ту же папку, например «Загрузки» или `C:\`) и запустите `start.bat` из новой папки.
3. Программа сама найдёт прежнюю установку и **не создаст новую базу**. В браузере откроется страница «Перенос базы»
   со списком найденных баз (число токенов, событий эмиссии, дата изменения). Нажмите «Перенести» у нужной.
   - Если прежняя папка в другом месте, укажите путь к её `data\scanner.db` в поле на той же странице или запустите:
     `.venv\Scripts\python.exe -m app --import-db "C:\старая_папка\data\scanner.db"`.
4. Перенос проверяет целостность, сверяет число строк по всем таблицам и показывает отчёт.
   **Оригинал не изменяется**: прежнюю папку можно держать как резервную копию.
   Отчёт также сохраняется в `data\import-report-*.json`.
5. Отмена переноса: `.venv\Scripts\python.exe -m app --rollback-import`.
6. Рекомендуется запустить **`windows_check.bat`**. Он проверит режим работы SQLite, целостность базы и выполнит
   60-секундный стресс-тест на временной базе. Отчёт `data\selfcheck-*.json` можно передать на проверку.

Если 2.0.0 уже была запущена в новой папке и создала там пустую базу, 2.0.1 покажет на главной предупреждение
«найдена установка, где данных больше» с кнопкой переноса. Текущая база при переносе сохраняется в `data\backups`.

### Обновление с версии 0.x
Просто замените файлы программы (папку `data\` не трогайте) и запустите `start.bat`. При первом запуске база автоматически
мигрирует на схему v2; **перед миграцией создаётся резервная копия** `data\backups\scanner-…-pre-migration-v1-to-v2.db`.
Откат: `.venv\Scripts\python.exe -m app --rollback-migration` (текущая база при этом тоже сохраняется рядом).

Если что-то не работает — запустите **`diagnose.bat`**: он проверит Python, пакеты, права на запись и доступ к каждому API.

На Linux/macOS: `./start.sh`.

## Что делает программа

### Поиск (Discovery Engine)
- Получает **новые пулы** из GeckoTerminal по включённым сетям, выделяет токены, объединяет пулы одного токена.
- Учитывает токен как **сеть + адрес контракта** (не тикер и не пара). Одинаковые тикеры разных проектов не смешиваются.
- Исключает стандартные quote-активы (WETH, USDC, USDG…) и токенизированные акции.
- **Исторический добор**: активные пулы младше 90 дней из топа по объёму и недавние протоколы DefiLlama с адресом токена.
- Ведёт журнал **покрытия**: какой интервал создания пулов реально получен и где были разрывы. Сеть никогда не
  помечается «полностью просканированной».

### Пять обязательных фильтров (статусы PASS / FAIL / UNKNOWN)
С версии 2.0 отсутствие венчурного финансирования **не является фильтром**. Данные о раундах, суммах, оценках, аллокациях
и разлоках инвесторов сохраняются и показываются как факторы риска (например, привлечено $10 млн при MCAP $2 млн).
| Фильтр | Как проверяется |
|---|---|
| **Возраст** ≤ 90 дн. | Официальный TGE (если внесён) → иначе первая сделка/самый ранний известный пул (помечается «предварительно»). Новый пул старого токена не делает токен новым. Первый mint намного раньше торгов → ручная проверка. |
| **Circulating MCAP** ≤ $5 млн | MCAP Intelligence Engine: официальный circulating × проверенная цена → CoinGecko (только если CoinGecko указывает именно этот контракт) → GeckoTerminal/DEX Screener → ончейн-граница (totalSupply − доказанно заблокированные адреса). Тип: **CONFIRMED / ESTIMATED / UNKNOWN**; нажмите на MCAP — увидите формулу и источники. Диапазон через порог → ручная проверка; доказанная нижняя граница выше порога → FAIL; только totalSupply → показывается стоимость выпущенного предложения как верхняя граница, а не как MCAP. |
| **Просадка от ATH** ≤ 86% | Дневные свечи качественных пулов; аномальные хвосты отбрасываются; показываются ATH по хвосту, по закрытию и используемый. При неполной истории — оговорка. |
| **Реальная утилити** | PASS — проверяемая связь токена с работающим протоколом (адрес токена в листинге DefiLlama или gecko_id), ненулевые TVL/комиссии. Сайт сам по себе продуктом не считается. Отсутствие сайта/соцсетей/листинга — **UNKNOWN → ручная проверка** (новый проект может быть ещё не проиндексирован); FAIL — только при независимом доказательстве (ваша оценка, токенизированная акция). Отдельно — риск «токен не захватывает ценность». |
| **Живая экосистема** | TVL сети, стейблкоины, DEX-объём и комиссии за 30/90 дней (DefiLlama). Без динамики TVL и DEX-объёма/комиссий — UNKNOWN; подтверждённый PASS — только при всех трёх группах метрик. Маленькие растущие сети не исключаются. |

### Уровни отбора
**A** обнаружен → **B** предварительно подходящий (возраст/MCAP/просадка не FAIL + рыночный минимум) →
**C** DeFi-кандидат (подтверждена утилити) → **D** фундаментальная проверка (метрики протокола + ончейн) →
**E** список наблюдения (нет FAIL, предварительная оценка ≥ порога).

Итоговые статусы: PASS, FAIL, UNKNOWN, MANUAL REVIEW, STALE DATA, DATA ERROR. Для каждого исключённого
кандидата сохраняется точная причина и доказательства; все изменения статусов журналируются.

### Фундаментал, токеномика, безопасность
- **DefiLlama**: TVL и динамика 7/30/90 дн., комиссии, выручка протокола, выплаты держателям (раздельно!), DEX-объём,
  займы и утилизация для lending, доля в категории на сети, методология источника.
- **Tokenomics Watchdog** (EVM): totalSupply, все mint/burn-события с транзакциями (с продолжением после перезапуска),
  восстановленная история предложения и **сверка с totalSupply()**, крупнейшие получатели с метками адресов,
  версии токеномики, **сравнение заявленного бюджета эмиссии с фактическими mint**.
- **Безопасность**: индикаторы по байткоду (mint, pause, blacklist, upgrade, roles, налоги), прокси EIP-1967/1167,
  owner()/minter() и их тип (EOA или контракт). Это индикаторы для проверки, а не заключение о безопасности.

### Сигналы, оценка, экспорт
- Журнал сигналов: новый кандидат, TGE подтверждён, MCAP установлен, TVL быстрее/медленнее сети, рост комиссий при плоском TVL,
  рост выручки N недель, падение комиссий N недель, всплеск эмиссии, mint выше бюджета, падение ликвидности, конфликт MCAP,
  смена owner/minter/реализации, предстоящий unlock, устаревший источник. Сигналы роста подавляются при смене методологии DefiLlama.
- **100-балльная матрица** с объяснением каждого пункта; непроверенные пункты не получают «средний» балл.
- Экспорт таблицы в **CSV** и **XLSX**; резервные копии базы.

## Как пользоваться

| Страница | Для чего |
|---|---|
| **Обзор** | Сколько пулов/токенов/кандидатов, покрытие по сетям, состояние API, последние сигналы |
| **Сканер** | Таблица всех токенов: сортировка по клику на заголовок, поиск, фильтры, экспорт |
| **Карточка проекта** | Вкладки: Фильтры (почему PASS/FAIL), Метрики, Фундаментал, Токеномика, Безопасность, Оценка, Пулы, История, Ручные данные |
| **Ручная проверка** | Кандидаты без FAIL, у которых часть критериев UNKNOWN, и что именно проверить |
| **Наблюдение** | Ваш список со статусами «Изучаю / Наблюдаю / Есть позиция / Гипотеза под вопросом / Архив»; повышенный приоритет обновления, даже если проект старше 90 дней |
| **Скрытые мной** | Токены, исключённые вами из «лучших кандидатов» (бессрочно или на 7/30 дней), с причиной и кнопкой «Восстановить». Из общей базы они не удаляются |
| **Токеномика** | Сводка supply, mint/burn, версии токеномики, сверка |
| **Сигналы** | Журнал сигналов с условиями, значениями, источниками и ограничениями |
| **Источники данных** | Сети, провайдеры, покрытие, разрывы, ошибки, лимиты, диагностика |
| **Настройки** | Все пороги фильтров, сети, интервалы, фоновый сбор, лимиты API, ключи, резервные копии |

### Внести результаты своей проверки
В карточке проекта → **«Ручные данные»**: финансирование (с категорией и ссылкой), дату TGE, вывод по утилити,
эндпоинт circulating supply, новую версию токеномики (JSON с `max_supply`, `weekly_budgets`, `unlocks`), метки адресов.
Фильтры пересчитываются сразу. Ручные записи можно отключить — история сохраняется.

### Фоновый сбор
По умолчанию выключен. Включите в «Настройках» → «Фоновый сбор: включён». Интервалы по умолчанию: новые пулы — 20 мин,
кандидаты — 4 ч, фундаментал — сутки, недельный снимок, резервная копия — сутки. Реальная частота ограничена лимитами API.

## Где хранятся данные
Папка `data\` рядом с программой: `scanner.db` (SQLite), `settings.json`, `secrets.bin` (ключи, зашифрованы DPAPI),
`backups\`, `logs\scanner.log`. Для переноса на другой компьютер скопируйте папку `data`.

## Документация
- `docs/STAGE0_API_FEASIBILITY.md` — проверка API: фактические ответы, лимиты, что бесплатно, что нет
- `docs/METHODOLOGY.md` — методика фильтров, уровней, MCAP/FDV, ATH, скоринга
- `docs/LIMITATIONS.md` — журнал технических ограничений
- `docs/FEATURES.md` — список реализованных и нереализованных функций
- `docs/CONTROL_SET_REPORT.md` — проверка на размеченном наборе реальных контрактов (FABLES, BOW и др.)
- `docs/audit/AUDIT_RESPONSE_v0.2.0.md` — исправления по независимому аудиту с тестами «до/после»
- `evidence/fables/` — экспорт 20 587 событий выпуска FABLES со сверкой с totalSupply (проверка: `python scripts/verify_supply_export.py evidence/fables`)

## Для разработчика
Python 3.11+, FastAPI, SQLite, httpx, ванильный JS + Chart.js (в комплекте, `app/web/vendor`). Версии зависимостей зафиксированы (`requirements.txt`; для тестов — `requirements-dev.txt`). Тесты: `pip install -r requirements-dev.txt`, затем `python -m pytest tests`.
Структура: `app/sources/*` — адаптеры API; `discovery.py`, `enrich.py`, `filters.py`, `fundamentals.py`, `onchain.py`,
`scoring.py`, `alerts.py`, `pipeline.py`, `jobs.py`, `api.py`; интерфейс — `app/web`.
