# Методика

## Единица учёта
`uid = <сеть>:<адрес>`. EVM-адреса приводятся к нижнему регистру; Solana mint-адреса сохраняются как есть
(base58 регистрозависим). Один тикер может принадлежать множеству токенов; один токен — торговаться во многих пулах;
один протокол — иметь несколько токенов. Пулы хранятся отдельно (`pools`), связь с протоколом — отдельно (`protocol_slug`).

## Типы дат (не смешиваются)
| Дата | Где хранится | Источник |
|---|---|---|
| Первое обнаружение нашей системой | `tokens.first_seen_at` | локально |
| Создание конкретного пула | `pools.pool_created_at` | GeckoTerminal / DEX Screener |
| Самый ранний известный пул токена | `facts.earliest_pool` | min по всем сохранённым пулам |
| Первая сделка | `facts.ath.first_trade_at` | первая дневная свеча с объёмом (точность — сутки) |
| Официальный TGE | `manual_facts(tge_date)` | документация/объявление, со ссылкой |
| Первое ончейн-событие mint | `facts.onchain.first_mint` | eth_getLogs (только если история сходится с totalSupply) |
| Возраст протокола | `facts.protocol.listed_at`, `first_tvl_at` | DefiLlama |

## Возраст
Начало публичного обращения = TGE (если внесён), но если торговля началась раньше TGE — более ранняя дата торгов.
Без TGE — min(первая сделка, самый ранний пул), статус PASS помечается **предварительным**.
Если первый mint на 30+ дней раньше первых торгов — UNKNOWN (вероятны ранние пулы вне покрытия).

## Цена
Медиана цены нашего токена по **качественным пулам**: токен участвует в паре и известна ИМЕННО его цена (в GT для
quote-стороны используется `quote_token_price_usd`; в DEX Screener для quote-стороны цена не берётся), ликвидность ≥ порога,
контр-актив из списка доверенных (или с CoinGecko id), отклонение от медианы ≤ порога. Исключённые пулы показываются с причиной.

## MCAP и FDV
- Кандидаты circulating MCAP: официальный эндпоинт × цена (`confirmed`), ручной circulating × цена, `market_cap_usd`
  GeckoTerminal (CoinGecko), `marketCap` DEX Screener. Если MCAP источника совпадает с его FDV (±0.5%) — это помечается
  `not_evidence` и не используется как доказательство.
- FDV(totalSupply) = цена × totalSupply (RPC или GT); FDV(max) = цена × max supply из актуальной версии токеномики.
- PASS: все пригодные кандидаты ≤ лимита. FAIL: все > лимита. Источники по разные стороны → UNKNOWN.
- Нет circulating, но FDV(totalSupply) ≤ лимита → предварительный PASS (circulating ≤ totalSupply на этой сети;
  не применимо к мультичейн-токенам — есть оговорка). FDV > лимита без circulating → UNKNOWN (не FAIL).
- Расхождение пригодных источников > 15% → запись в `conflicts` и сигнал.

## ATH и просадка
Дневные свечи (до 3 качественных пулов, GeckoTerminal OHLCV с параметром `token=<адрес>`). Хвост свечи
`high > k × max(open, close)` (k=2 по умолчанию) считается аномалией: ATH по такой свече = верх тела. Показываются ATH
используемый, сырой максимум, максимальное закрытие. История полна, если первая свеча не позже чем через 2 суток после
самого раннего известного пула. Наблюдаемая просадка — нижняя граница истинной, поэтому FAIL надёжен и при неполной истории,
а PASS при неполной истории — предварительный.

## No-VC
Категории: VC-фонд, ангел, грант, публичная продажа, стратегический партнёр, рыночная покупка, экосистемное финансирование,
«отсутствие внешнего финансирования задокументировано», «проверено — упоминаний нет». FAIL — категории из настройки
`vc_fail_categories` или раунды с инвесторами в DefiLlama raises. PASS — только `none_documented` со ссылкой.
Отсутствие новостей и пустой `raises` — не доказательство.

## Утилити
PASS: проверяемая связь с протоколом DefiLlama (совпадение `address` или `gecko_id`, либо ручная запись) и активность
(TVL > 0 или комиссии > 0). FAIL: токенизированная акция; нет листинга, сайта и соцсетей. Иначе UNKNOWN.
Риски захвата ценности (нет holders revenue) выводятся отдельно.

## Экосистема
Негативные признаки: TVL < порога, падение TVL за 90 дн. ниже порога, падение стейблкоинов, DEX-объём 30 дн. ниже порога.
≥ 2 признака без роста → FAIL; 1 признак → UNKNOWN (или PASS при росте > 10% за 30 дн.).

## Уровни и статусы
См. README. Рыночный минимум уровня B — ликвидность и объём 24ч (настраиваются). STALE DATA — рыночные данные старше
`stale_hours`. UNKNOWN не даёт статуса «прошёл», но и не скрывает проект: при уровне ≥ B он попадает в «Ручную проверку».

## Скоринг (100 баллов)
8 критериев (20/15/20/15/10/10/5/5), каждый разбит на пункты с явным условием. Нет данных → пункт «не проверено», 0 баллов,
и он исключается из «проверяемого максимума». Показываются подтверждённые баллы, проверяемый максимум, покрытие,
предварительная оценка (= подтверждённые / проверяемый максимум × 100) и блокирующие риски. Оценка не является рекомендацией.

## Воспроизводимость
Фильтры и скоринг — чистые функции от сохранённых фактов; одинаковые факты дают одинаковый результат (есть тест).
Исходные ответы API сохраняются в `raw_responses` (gzip), наблюдения — в `observations` без перезаписи.
