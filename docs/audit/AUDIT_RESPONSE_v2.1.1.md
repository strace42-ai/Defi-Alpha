# Ответ на аудит ZIP 2.1.0 → 2.1.1

Изменён только `app/emission_pressure.py` и его отображение в `app/web/analytics.js`. Изменения в интерфейсе: метка «заявлено,
не проверено», формат «подтверждено ≥ X%». SQLite, котировки, DefiLlama, ATH, ончейн-индексация и Momentum не затрагивались.
Протоколы проверки:

- `docs/audit/v2.1.1_regressions_after_fix.txt`: 4 проходят; весь набор — 145.

## Дефект 1. Преждевременный FINAL использования бюджета
**Воспроизведение** (`test_211_utilization_not_final_while_unclassified_mints_remain`). Неделя 1: mint 5M на размеченный gauge и mint 2M
на неизвестный адрес. Версия 2.1.0 выдавала `final`, 50%. Неизвестные 2M тоже могут быть LP-эмиссией, поэтому значение не доказано.

**Исправление.** Каждый mint эпохи относится к одной из групп:

| Группа | Состав |
|---|---|
| `confirmed_lp` | LP-категория с подтверждённой ролью |
| `unconfirmed_lp` | LP-категория, роль `probable` или `claimed` |
| `unclassified` | mint неизвестного назначения, на minter, прочая эмиссия, а также не-LP категории с неподтверждённой ролью — всё, что может оказаться LP |
| `proven_non_lp` | Genesis, аллокация, mint в escrow — с подтверждённой ролью |

- `classification_complete` = нет `unconfirmed_lp` и `unclassified`. Это доказанная полнота охвата эмиссионных контрактов для эпохи.
- **FINAL** — только при полной классификации, завершённой и полностью просканированной эпохе с точными границами.
  `value_pct` выдаётся только в этом случае.
- **PARTIAL** — `confirmed_pct` (нижняя граница) и `upper_bound_pct`; полная доля бюджета не выдаётся.
- На уровне токена `lp_emission.amount` — только подтверждённая сумма. Отдельно указываются `unconfirmed` и `unclassified_post_tge`,
  а `complete=false`, пока полнота не доказана.

Положительный случай (`test_211_utilization_final_only_when_all_epoch_mints_proven`): после подтверждения роли второго адреса как
`team_vesting` неделя 1 получает FINAL 50%. Неделя 2, где только gauge, — FINAL 40,8%.

Тест `test_09` из 2.1.0 ожидал FINAL для недели 1, то есть закреплял дефект. Он исправлен на новую семантику:
неделя 1 — PARTIAL ≥ 50%, неделя 2 — FINAL.

## Дефект 2. `claimed` автоматически превращался в `probable`
**Воспроизведение** (`test_211_claimed_role_is_not_promoted_to_probable`, `test_211_evidence_levels_preserved_exactly`).
В 2.1.0 роль gauge с достоверностью `claimed` давала LP-эмиссию с доказательностью `probable`. Метка 2.0, введённая пользователем,
давала Genesis `probable`.

**Исправление.** `ev_level = conf`, если `conf` ∈ {confirmed, probable, claimed}, иначе `unknown`. Доказательность категории и LP-эмиссии
определяется по самому слабому элементу (`weakest`). Genesis разделён на `confirmed`, `probable` и `claimed`.

  `integrity_check = ok`, 0 ошибок.

  0 отличий в 3 805 решениях фильтров, лучшие кандидаты те же (`docs/release_2.1/compare_2.0.1_vs_2.1.1_*`).

  бюджета по-прежнему «не проверено». Genesis 15M остаётся подтверждённым: роль Seeder Safe взята из официальной документации.
